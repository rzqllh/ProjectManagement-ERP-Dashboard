# UI/UX Guideline

## Visual Direction

Current visual direction is dark command-center/glass dashboard. Keep it consistent.

Recommended identity:

- Serious.
- Operational.
- Premium internal-tool feel.
- High information density but still readable.
- PMO control center, not generic admin dashboard.

## Design Principles

### 1. Every page needs a clear job

Each dashboard page must answer:

- What is this page for?
- What should the user do first?
- What is currently risky/important?
- What changed recently?

### 2. Prioritize operational clarity over decoration

Glass, glow, gradients, and animations are okay, but only if they support hierarchy.

Avoid:

- Too many glowing colors at once.
- Low contrast text.
- Dense cards without grouping.
- Buttons with unclear priority.
- Decorative motion that distracts from PMO data.

### 3. Use consistent page anatomy

Recommended page layout:

```txt
Page Header
  - Title
  - One-line description
  - Primary action
  - Optional secondary action

Control Bar
  - Search
  - Filters
  - Sort
  - View toggle

Main Content
  - KPI / summary cards
  - Table / board / graph / detail panels

Support States
  - Loading
  - Empty
  - Error
```

## Component Standards

### Buttons

Use clear priority:

- Primary: one per section/page.
- Secondary: useful but less important.
- Ghost: navigation or low-emphasis actions.
- Destructive: delete, revoke, disconnect.

### Cards

Cards should have:

- Clear title.
- One main purpose.
- Consistent padding.
- Consistent radius.
- Optional subtitle/helper text.

### Tables

Tables should include:

- Search.
- Filter.
- Empty state.
- Loading skeleton.
- Row actions.
- Status badges.
- Responsive fallback for small screens.

### Forms

Forms should include:

- Field labels.
- Helper text for ambiguous fields.
- Validation messages.
- Cancel action.
- Save action.
- Disabled/loading submit state.

### Status Badges

Use consistent mapping.

Example:

```txt
not_started -> neutral
in_progress -> blue/cyan
blocked -> red/orange
risk -> amber
escalated -> red
done -> green
cancelled -> muted
```

## Required States

Every data-driven UI must handle:

### Loading

- Skeleton for list/table/card content.
- Avoid blank screen.

### Empty

Empty state should tell the user:

- What is missing.
- Why it matters.
- What to do next.

Example:

```txt
No generated documents yet.
Generate an evidence report or attendance sheet from this project to keep operational records organized.
[Generate Document]
```

### Error

Error state should include:

- Short error message.
- Retry action if applicable.
- No raw stack trace.

### Success

Use toast/inline feedback for:

- Create.
- Update.
- Delete.
- Export.
- Upload.
- AI answer generated.

## Dashboard Guideline

The dashboard should answer these questions quickly:

1. How many projects are active?
2. Which projects are blocked?
3. Which decisions are waiting?
4. Which ND records are escalated?
5. Which stakeholders need attention?
6. What changed recently?
7. What action should the PMO take today?

Recommended dashboard sections:

- Project Health Overview.
- Active Blockers.
- Decision Queue.
- Escalation Radar.
- Recent Activity.
- AI Recommended Actions.

## Project Detail Page Guideline

Recommended tabs:

```txt
Overview
Sections
Tasks
Risks & Issues
ND Records
Decisions
Documents
Knowledge Base
Timeline
```

The project detail page is where the three flagship modules connect:

- Tracking.
- Document generation.
- AI knowledge.

## Document Generator UX

Use a guided flow:

```txt
Step 1: Choose document type
Step 2: Select project / source data
Step 3: Fill required fields
Step 4: Upload supporting photos/data
Step 5: Preview
Step 6: Export and save
```

Document types:

- Absensi.
- Evidence.
- Form kebutuhan.

Each generated document should show:

- Document type.
- Project.
- Generated by.
- Generated at.
- Status.
- Export/download action.

## AI Assistant UX

AI panel should not feel like a generic chatbot.

Use PMO-specific quick prompts:

- Summarize current project risks.
- What is blocking this project?
- Create weekly progress summary.
- Extract action items from latest document.
- Which decisions are overdue?
- Recommend next PMO actions.

AI answer card should include:

- Summary.
- Risks.
- Recommended actions.
- Source/citations if document-grounded.
- Confidence level.

## Mobile Guideline

Internal dashboards are often desktop-first, but basic mobile responsiveness is still required.

Minimum:

- Header does not overflow.
- Navigation collapses.
- Tables have card/list fallback or horizontal scroll.
- Forms are usable on mobile.
- Primary actions remain visible.
